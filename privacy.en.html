Requota Privacy Policy

Last updated: September 20, 2026

Requota displays quotas from AI services you connect. We do not operate a server that receives your accounts, credentials, quota history, or chat content. The app contains no ads, tracking, or third-party analytics SDKs.

Data stored on your Mac

Account names, email addresses, service settings, file permissions, and quota history are stored locally. The App Store version uses its own macOS sandbox. Credentials from direct sign-in and API keys you enter are stored in Requota's Keychain items. The direct-download version uses a local configuration file with private permissions. Quota history is kept for up to 30 days and contains no authentication tokens, prompts, or response text. Warm-up and notification deduplication records are kept with the account.

Connecting other tools

Requota reads a file or folder only after you select it. For a local Codex connection, it reads the selected auth.json and uses its credentials to query the relevant service. Codex continues to manage those credentials. Access is read-only: Requota does not modify Codex configuration or read another tool's Keychain items.

Project usage analysis requires a separate selection of a Codex sessions folder. Requota reads session records locally and extracts only timestamps, task identifiers, working folders, repository grouping identifiers, model names, and token counts. It does not save prompts or response text or upload these records. The usage index retains up to 12 months of observations. File positions support incremental updates, and the folder permission remains until you stop analysis.

Real-time monitoring uses the same sessions-folder permission to watch file changes and calculate token increments. CPU, memory, and network rates are calculated locally using system APIs. Requota does not read network traffic contents or upload system metrics. Recent five-minute charts remain in memory. You can pause sampling or choose which metrics appear in the workbench and menu bar.

Response performance is an optional source. You can separately select an exported codex-lb request database or a folder containing store.db. Requota reads successful requests' timestamps, models, output and reasoning tokens, time to first response, generation time, and queue time. It excludes internal warm-up requests. It does not read the accounts table, keys, prompts, response text, or client addresses. Permission is stored locally; up to 30 days and 100,000 request records are summarized in memory and never uploaded. Disconnecting the source in the response-performance menu clears its permission and cache without changing the original database.

Data sent to providers

When you sync Codex, OpenAI API, or Zhipu, requests go directly to that provider or to the address you configured. They include the credentials and parameters needed for authentication. Providers also receive ordinary network connection information. Each provider's privacy policy governs how it retains and processes this data. Direct sign-in takes place on the provider's website; Requota does not receive your password.

Providers may retain account identifiers, request times, service usage, IP addresses, and diagnostic records to provide and protect their services and improve them. OpenAI may infer an approximate location from your IP address. The App Store privacy label covers processing by directly connected providers. It does not mean Requota uploads your local project logs, system metrics, or conversations. Provider retention depends on their policies and your account settings; disconnecting Requota does not delete data they already hold.

If you enable warm-up for a Codex account, Requota sends a short “hello” message to that account's service when the conditions are met. That message uses a small amount of model quota. Ordinary quota checks do not send model messages. Turn off warm-up to stop future automatic triggers.

Sample workbench

“View Sample” opens a separate workbench without connecting an account. Sample accounts, quotas, usage, and system charts are synthetic and kept only in memory. Simulated warm-up sends no messages; closing the sample discards its changes.

Purchases and restoration

The App Store handles the lifetime Pro purchase. Requota uses StoreKit to read products and system-verified transactions and determines access locally. We do not receive your payment-card details or App Store password, or upload transaction receipts to a developer server. Apple processes purchases and store-account information under its own privacy policy. “Restore Purchases” may ask you to verify your App Store account. Removing an AI service account or deleting usage records does not cancel Pro.

Your controls

You can pause monitoring, turn off warm-up and notifications, clear history, or remove an account. Removing an account deletes its credentials, history, and deduplication records saved by Requota. It does not sign you out of the provider or revoke the provider's server-side token. To revoke access completely, use the provider's account controls.

Usage analysis is independent of account monitoring. In its source menu, you can stop analysis and delete the local index and folder permission. Original Codex sessions are not deleted.
